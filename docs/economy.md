# 轻量模型：以客户回复为目标

软件的当前目标是找到合适客户、展示有针对性的产品与服务、取得回复。报价和成交由销售继续推进。本版不扩展计费、账号售卖或多租户功能。

## 让模型做小任务

使用 [economy.json](../examples/economy.json)，或在已有配置加 `"workflow": {"mode": "economy"}`。新客户会记录使用的模式；已经开始的旧任务保留原流程，避免重新生成。

| 环节 | 谁负责 | 最低所需能力 |
| --- | --- | --- |
| 找客户及官网 | 联网研究接口/Agent | 实际搜索、打开官网、返回来源 |
| 材料方案＋邮件片段 | 小型文字模型，一次调用 | 根据少量事实选目录 ID，输出简短 JSON |
| 排版、服务说明、回复问题、签名、防重 | 程序 | 不消耗模型调用 |
| 单张 A/B 效果图 | 独立生图接口 | 使用真实产品/材料参考图 |
| 产品及数量核对 | 小型视觉模型 | 看两张图，返回三个布尔值 |

模型不必自己规划流程、操作邮箱或反复审稿。轻量路径仍是研究、文字、图片、身份核对四次 API 调用；相较 balanced 模式，**它让文字任务不再依赖视觉模型，不是凭空减少到一次模型调用**。短输出和固定格式能减少任务复杂度，实际速度与可用率仍需用你选的模型测试。

不按 GPT 版本号判断能力，不强制某个旗舰型号。文字、研究、视觉和生图可以用不同厂商：

- 简单配置可增加 `api.research_model`、`api.vision_model`，文字使用 `api.text_model`。
- 独立接口可配置 `providers.research`、`providers.text`、`providers.vision`、`providers.image`。
- 纯文字模型标记 `vision: false`，不会把图片偷偷丢掉后假装完成核对。
- 不支持 JSON mode 的 Chat 接口使用 `json_mode: "prompt"`；它仍需实际输出合法 JSON，可带标准代码围栏。
- 旧 Chat 接口可用 `token_limit_parameter: "max_tokens"`。不支持 reasoning 参数时不配置它。

**兼容接口不等于所有最弱模型都能胜任。**程序不会把无联网、无视觉的普通聊天模型变成搜索器或生图器，也不会自动换成更贵模型、追加付费接口或反复修复错误输出。`doctor` 检查配置和明确的能力冲突；真实调用才证明兼容性。

## 每封邮件为什么值得回复

轻量模式的邮件固定包含：官网上的一个实际产品细节 → 针对该产品的 A/B 方案价值 → 你确实能提供的服务 → 一个可直接回答的 A/B 问题。

文字模型输出 `email`：`subject`、`fact_index`、`opening`、`a_value`、`b_value`、`service_id`。开头必须含选中的完整官网事实，服务只能选择配置里的 ID。程序添加服务原文、样品验证说明和一句回复问题，不让模型编造 MOQ、交期、价格或证书。

在每个 brand 下配置 `services` 字典，仅填写你确实提供的服务。例如确认能定制盒型、内托和表面工艺后，可填写：

```json
{"services":{"custom_packaging":"We can tailor the box structure, insert and finish around your product."}}
```

没有提供服务资料时，默认只说明已制作的产品概念。A/B 价值仍由模型根据方案写作，程序的来源绑定不保证模型的每一句话都正确；不要把泛泛夸赞、无证据的痛点或购买意向当成个性化价值。

`metrics` 与网页中的 `outreach_results` 按已接受邮件的不同联系人统计回复、退出和拒绝。同一人多次回复只算一人；未发送联系人不进入回复率分母。当前收信解析可能把自动回复列为回复记录，所以该指标不是积极回复率、商机率或成交率。

## 暂缓的功能和术语

- “选择生图服务”：比较不同服务在同一类真实参考图上的耗时、产品保持程度、可用图比例和成本；不会自动更换你的付费服务。
- “客户隔离”：将来把软件交付给不同公司时，其邮箱、客户和资料互不混用。当前不新增这套商业系统。
- “用量与计费”：将来记录软件客户用了多少请求并收费。当前不开发；获客回复记录与此不同。

[OpenAI 延迟指南](https://developers.openai.com/api/docs/guides/latency-optimization)讨论合并串行请求、减少输出和使用固定程序；[结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs)区分 JSON mode 与严格 schema 输出。此工具保留较简单的 JSON/提示词两种适配方式，不要求所有接口都支持严格 schema。

# 从包装业务扩展到其他外贸产品

通用流程负责：寻找合适企业 → 官网证据及公开邮箱 → 真实产品研究 → 定制方案 → A/B 效果图 → 价值邮件 → 发送结果/回复记录。

产品配置负责：卖什么、适合什么客户、可做哪些结构和材料、怎样表达产品价值、哪些要求需实物验证。无需修改发送或恢复代码。

新配置示例使用 `product_profile: "paper-packaging"`，覆盖各类适合纸盒、礼盒的企业及公开经营小微商家，不设最低售价。包装配置需要官网目标 SKU 的准确 USD 售价：低于 USD 50 只推荐卡纸折叠盒并固定说明 1000 个起订；达到或高于 USD 50（含 50）只推荐硬盒。完整的第二种示例为 [零售陈列架](../examples/retail-displays.json)：非包装配置可不要求客户公开零售价，也不受盒型规则限制。示例是配置模板，不宣称该行业已完成真实商业验收。

## 配置协议

在 `product_profiles` 里建立一个命名对象，通过全局或账号的 `product_profile` 选择：

| 字段 | 用途 |
| --- | --- |
| `name`、`offer` | 产品名称及真实可提供的定制服务 |
| `target` | 该产品的目标客户；账号的 `target` 优先于全局 `target`，再使用这里的值 |
| `structures` | 至少两个 ID → 描述；盒型、展示架结构或其他可呈现的产品形式 |
| `supports` | 内托、货架、支撑等 ID；不需要时可明示 `none` |
| `accessories` | 可选辅料 ID，每方案最多两个 |
| `design_rules` | 产品适配、材料和物理结构约束 |
| `validation_note` | 邮件中需说明的实物/工程验证事项 |
| `price_policy` | `required`、`minimum`、`currencies`；不需要公开零售价时 `required: false` |
| `price_tier_policy` | 包装专用的价格分层、结构集合和卡纸起订量；内置包装配置固定为 `usd50-v1` |
| `material_manifest` | 可选私有参考图清单，相对配置文件解析 |

方案输出使用 `structure` 和 `support`。旧接口的 `box`、`insert` 仍兼容。客户资料和引用页面始终是数据，不能更改发件人或产品配置。

一个工作目录支持多个销售身份、多个产品配置。不同商业客户应使用**独立工作目录、配置、API/邮箱凭据与私有资料目录**；不要将彼此的客户记录或私有素材放进同一实例。当前仅提供本地单用户服务，不是已完成租户隔离、登录与计费的 SaaS。

当前可用于可视化定制实体产品。工程参数、医疗功效、认证等不能从概念图推断。针对其他行业需要提供自己的产品规则和有权使用的材料参考。

内置包装分层只接受官网目标 SKU 的准确 USD 价格。价格正好 USD 50 进入硬盒层；低价层的 MOQ 是供应方业务条件，由程序加入邮件而不是让模型生成。任何价格证据、层级、A/B 结构或 MOQ 不一致都会在最终发送闸门被拦截。

软件采用仓库中的 MIT 许可证；私有品牌素材与客户资料并不因导入而公开。商业部署、行业配置和支持可在独立交付中提供，具体商业条款另行约定。

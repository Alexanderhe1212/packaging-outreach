# User Radar + OutreachPilot Windows 试用版使用说明书

版本：1.4.0-local / Windows preview 2026-10-28

## 1. 先了解这个包

这是基于现有源码制作的 Windows 试用启动包，使用浏览器显示界面，需要先安装 Python。它不是已经通过 Windows 实机验收的 EXE/MSI 安装程序，也不是 macOS 桌面外壳的直接复制。

包内没有原用户的账号配置、密码、API Key、客户数据库、已发邮件或运行日志。客户需要自行配置自己的公司信息、模型服务及邮箱；模型服务可能收费，费用由相应服务商收取。

可用入口：OutreachPilot 图文开发信工作台、User Radar 官网公开联系人研究页面。原 Mac 的 launchd 常驻调度、桌面总控和浏览器插件配对没有移植到此试用包；不要把它当作完全无人值守版本。Radar 的 AI 搜索依赖另行配置的 Codex CLI，当前试用包不安装或配置该依赖；请先使用官网网址研究和工作台已有的模型搜索。

## 2. 安装与打开

1. 在 Windows 上安装 Python 3.11 或更新兼容版本，并安装 Python Launcher（安装器通常默认提供）。不要从未知来源获取 Python。
2. 解压整个 ZIP 到普通可写文件夹，例如 `C:\UserRadarCustomer`。不要直接在压缩包里启动。
3. 双击 `Setup.cmd`。它会创建独立的 `.venv`，从 Python 包索引安装依赖；需要联网。失败时保留窗口里的报错，不要继续发信。
4. 完成后双击 `Start.cmd`。成功时浏览器打开工作台；命令行窗口保持打开。
5. 工作台：`http://127.0.0.1:18800`。官网研究页：`http://127.0.0.1:18830`。

打开应用不会自动开始发信。每次通过此启动器打开时，已配置账号都会先恢复为暂停状态，再由你明确启动。若端口已被占用，启动器会拒绝启动，不会强行结束别的程序。

## 3. 首次配置

在工作台的设置中填写：

- 模型连接：服务商、API 地址、你自己的 API Key，以及可实际使用的搜索、写信、图片模型。预设列表不是服务商可用性保证，模型名称以你实际账号支持的为准。
- 邮箱账号：公司名称、发件人显示名、发件邮箱、SMTP/IMAP 地址与端口、邮箱授权密码、公司官网和真实签名。
- 产品方案：选择定制包装，核对能实际提供的结构、材料与服务。预置文案不是你的工厂能力证明，发送前应调整。
- 目标区域：美国、英国、欧洲、澳大利亚。可在账号中覆盖产品方案默认市场。
- 搜索品类：填写实际能服务的产品品类，例如美妆、珠宝、蜡烛、咖啡、茶、食品、文具或小型消费品；排除包装设备及工业机械供应商。

不要使用原开发者的账号或冒用 MTT/GUKA 身份。页面若保留 MTT/GUKA 的文字提示，那是旧界面文案，不表示包内提供了这些邮箱。

初次试用建议关闭账号的自动发送，先做少量准备和人工审核。连接测试会访问所配置的服务，完成公司和账号配置后再由你点击。不要把账号密码发给软件开发者。

## 4. 开发一位客户的流程

1. 在官网研究页输入客户官网，查询公开联系人与邮箱。公共商务邮箱可保留为公司联系人；只有来源明确对应的人名才能作为具名联系人，不能从邮箱前缀猜名字。
2. 查看产品适配、邮箱来源、联系人证据。客服、媒体、招聘、隐私邮箱不能作为采购负责人统计。
3. 本试用包采用手动交接：在 OutreachPilot 的添加客户入口，选择你的账号并粘贴官网网址。不要把“导入不联系名单 CSV”当作客户导入，那是阻止联系的名单。
4. 工作台会根据现有流程核实官网、邮箱和产品，生成文案与包装概念图，执行发送前检查。只有通过检查才能进入待发送。
5. 审核通过后，按照账号当前的发送设置启动。首次建议用你自己控制并明确同意接收的测试邮箱验证收信、图片和签名，再接触真实客户。

如果使用工作台的自动发现，须先配置支持搜索的模型连接和账号目标类型。此功能与 Radar 的 Codex 搜索是不同入口，不能把一个入口启动视为所有后台任务都已开启。

## 5. 发出前检查清单

- 有可验证姓名时称呼本人；无姓名时称呼公司团队，不猜 CEO 或采购负责人。
- 开头是已核实的产品观察；痛点用条件表达，不能声称客户确实有某个问题。
- 包装建议与产品有关，不捏造价格、MOQ、交期、认证或案例。
- 图中的单件、套装数量、材料包/成品形态与官网一致，不将套装画成单件。
- 概念图是建议方案，不是已打样或量产实物照片；不要误导客户。
- 发件公司与签名属于你自己的账号，包含合适的身份与退订方式。

本包保留已有的图像检查、去重、抑制和冷却逻辑，不通过图片检查不应降级为无图发送。不要通过清数据库、换邮箱账号或反复重试来规避保护。

## 6. 状态怎么看

| 状态 | 含义与操作 |
|---|---|
| 排队中 / 读官网 / 写邮件 / 生成图 | 正在不同阶段准备；查看详情，不要重复添加 |
| 待发送 | 准备完成；仍需遵守账号发送设置与保护 |
| SMTP 已接受 | 服务器接受了发送请求，**不等于送达或进入收件箱** |
| 待核实发送 / unknown | 发送结果不明确；不能直接重发，先核实邮件记录 |
| 等待官网 / 限流 | 来源要求等待，按系统重试时间处理，不代表邮件发送失败 |
| 失败 / Needs Attention | 打开问题列表查看具体阶段与原因，不能一律按重发处理 |
| 已回复 | 查看内容，区分自动回复和真人回复，不继续自动开发信 |
| 退信 / 退订 | 保持抑制，不继续发送 |

图像失败只处理图文准备问题；已发出、未知结果、退信、退订或已回复记录不能因为修改图片而重新投递。自动回复和真人回复应分别观察，不能把自动回复算为有效询盘。

## 7. 暂停与关闭

先在工作台暂停账号，等待当前任务结束，再回启动窗口按 `Ctrl+C` 关闭服务。关闭浏览器标签不会关闭后台。不要在“发送中”时强行关机；意外中断后产生的未知结果必须核实，不得盲目重发。

## 8. 数据位置与备份

客户数据和日志位于 `%LOCALAPPDATA%\UserRadarCustomer`。主要包括 `OutreachPilot` 下的账号配置、密钥文件、SQLite 数据库与生成内容，以及 `UserRadar` 下的联系人数据库与配对文件。

完全停止应用后，复制整个上述目录进行备份。不要只复制一个正在运行的 SQLite 文件；避免遗漏 WAL 内容。备份包含敏感信息，妥善保管；不要把使用后的文件夹或 `.venv` 打包发送给别人。恢复前先保留当前目录副本，同一客户不要同时启动两份恢复副本发信。

## 9. 常见问题

| 问题 | 处理 |
|---|---|
| 提示找不到 py | 修复 Python 安装，安装 Python Launcher，再运行 Setup.cmd |
| 依赖安装失败 | 检查网络及 Python 版本，保留错误信息；不要关闭证书校验 |
| 端口被占用 | 关闭自己此前启动的应用；不要随意结束未知进程 |
| 模型报错 | 检查自己的模型名称、余额、权限及 API 地址；不要凭预设名称假设可用 |
| 官网有产品却读不到 | 动态渲染与 Codex 工具在此 Windows 试用包中尚未验收；可换用该官网公开产品详情页，不能绕过访问限制 |
| 邮箱验证失败 | 检查官网公开证据，不猜测邮箱、不把未核实邮箱强行标为通过 |
| 不发信 | 检查暂停、账号设置、待发数量、图像检查和保护原因；不要清除发送历史 |
| 收信很少 | SMTP 接受不能证明送达；先核对退信与收信配置，再检查客户匹配和文案 |

向支持方反馈时，提供版本、步骤、时间和脱敏错误截图。不要提供密码、API Key、完整客户数据库或原始邮件历史。

## 10. 验收边界

随包附 `验证报告.md`。本包在 macOS 上进行隔离的源码/本地服务检查，不能替代 Windows 实机启动、原生安装器、真实邮件投递或服务商连通性验收。正式交付客户长期使用前，需要在目标 Windows 电脑按本说明完成配置和受控测试。
